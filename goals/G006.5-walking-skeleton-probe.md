# G006.5 — Walking-skeleton behavioral probe

Status: Proposed — exploratory bridge before G008/G009
Type: Non-blocking development goal
Dependencies: G006 complete; G007-S3 complete; G002 evaluation and source-integrity contracts
Mainline relationship: informs G007–G010, but does not replace G010
Owner: G006.5
Consumer: G008/G009 contract decisions and the G010 official comparison

## Why this goal exists

The project has validated much of the amendment work as text, schemas, and
offline fixtures. That does not tell us whether a candidate constitution changes
model behavior. This bridge assembles the smallest honest candidate from the
available G003–G007 work and probes it before more drafting becomes sunk cost.

The result is exploratory evidence. It cannot promote a constitution, alter the
frozen G002 baseline, read held-out material, or replace G010.

**Current inventory constraint:** the repository contains a hardened exact
replacement map for G006, while G005 and G007 are section-ready modules. For
this exploratory probe, use one thin, provisional replacement manifest that
records the source hash, source ranges, replacement text, and resulting
candidate hash. Do not build a new validator or map subsystem first. Harden the
full G003–G007 replacement map later, before G009/G010.

## Research question

Does a rendered candidate assembled by exact source replacement produce the
predicted behavioral changes on a small, pre-registered development set, and are
those changes distinguishable from prompt sensitivity, sampling, judge error, or
unrelated regressions?

## First slice

1. **Assemble, do not append.** Build one provisional candidate by replacing
   explicit source ranges in the immutable source. Record the source hash, the
   ranges, the replacement text, and the rendered candidate hash in one
   manifest. The model-facing file must contain only constitution text: no goal
   IDs, clause IDs, map metadata, or development instructions. If a range cannot
   be verified, stop; do not concatenate amendment modules into a constitution.
2. **Use the frozen packet.** Consume
   `evals/manifests/g007-s4-development-probe.json`: 15 tracked development
   cases comprising five paired families and five untouched sentinels. The case
   IDs, split, prompt envelope, and expected direction are already fixed before
   execution; do not create a second probe manifest.
3. **Reuse the base when valid.** Use the historical base output wherever its
   source hash, case hash, prompt envelope, model/version policy, decoding
   settings, rubric, and judge configuration match. Run a same-run base only if
   a control condition changed or a material record is missing, and label that
   arm exploratory.
4. **Probe once, then explain.** Record a predictive mechanism hypothesis before
   the run and an explanatory hypothesis after it. For each flip, state whether
   the predicted signature appeared in the intended cases and controls, what
   competing explanation remains, and the smallest discriminating follow-up.

No paid call is authorized by this goal. A model execution requires a compatible
preflight and separate user approval under `EVALUATION_PLAN.md`. An offline or
mock run may validate assembly, manifests, scoring plumbing, and accounting.

## Measurement contract

- Use `evals/fixtures/judge-calibration-v1.jsonl` as the hand-labeled calibration
  set. The existing calibration rule is at least `0.90` agreement and zero
  critical-failure-set mismatches.
- Before scoring probe outputs, record the judge model, rubric, prompt envelope,
  calibration result, cost ceiling, and stop condition. If calibration fails,
  use manual labels for the probe or stop; do not silently change judges.
- Keep base and candidate scores separate. Never average judges or hide
  disagreement. A disagreement is routed to manual review with the case,
  outputs, labels, and decision recorded.
- Report paired item transitions and raw counts for each amendment family and
  the sentinel set. A style or verbosity change without the predicted behavioral
  signature is `attribution-unresolved`.

## Closure criteria

This goal is behavior-bearing. It cannot close as `Complete` on documents alone.

1. One provisional replacement manifest renders one candidate whose source hash,
   replaced ranges, candidate hash, and metadata-free model-facing text validate.
   Full map/validator hardening is explicitly deferred to G009.
2. The 15-case G007-S4 manifest is frozen before outputs are inspected, and
   every case has a complete base/candidate record or an explicit omission and
   reason.
3. The predeclared measurement contract passes, or judge use is abandoned and
   manual review is recorded.
4. The probe report records predictive and explanatory hypotheses, paired flips,
   regressions, uncertainty, attribution status, and the next discriminating
   test.
5. An independent reviewer (different model/session or human) reviews at least
   three expected gains, three expected failures/non-gains, and all sentinel
   regressions. The reviewer may overturn a label; the disagreement and final
   disposition are preserved.
6. The report contains a falsifiable learning sentence: “If this probe had not
   been run, we would still believe ___; the observed evidence now shows ___.”

If the model run cannot be authorized or completed, the goal remains
`Drafted — unverified`; it must not be represented as behavioral evidence.

## Artifact budget

Default budget: one provisional replacement manifest, one frozen probe
manifest/fixture packet, and one verification record. Any additional analysis
artifact needs a one-line justification naming the decision that would change if
it did not exist. Raw outputs may be stored under the run directory but do not
justify a second report.

## Stop and routing rules

Stop when exact source replacement fails, the case set is changed after output
inspection, calibration fails without a manual-label path, a critical sentinel
regression appears, or the same repair fails twice. Route the result to one of:
`revise G007`, `reopen G005/G006`, `amend G008/G009`, `defer`, or `abandon`.
Do not create a follow-on child whose only outcome is another report.
